# Failure Case Template

## Title

Short symptom plus root cause if known.

## Context

Project, robot, task, environment, date, and run id if available.

## Symptom

Observable behavior. Prefer metrics, logs, or video references.

## Impact

Safety, delivery, data quality, or training impact.

## Evidence

Commands, logs, reports, videos, metrics, or code paths.

## Hypotheses

List what was considered and how each was checked.

## Root Cause

State only if supported. Otherwise write `Unconfirmed`.

## Fix

Code, config, procedure, or operating change.

## Validation

How the fix was verified.

## Prevention

Checklist or process update.

## Automation Opportunity

What a script, skill, or agent could detect next time.

## Related Artifacts

Paths, run ids, commits, report links, or video names.
